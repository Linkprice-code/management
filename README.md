# 2-3팀(김재현) 날짜별 매출·업무관리 대시보드

기존 쇼핑검색광고·파워링크·GFA 매출관리 화면을 그대로 유지하면서 **기준일별 실적 조회와 사유/업무상태 기록**을 추가한 GitHub Pages 배포 버전입니다. **최연아·안희성은 항상 제외**합니다.

## GitHub Pages 업데이트

1. ZIP 압축을 풀어 `index.html`, `app.js`, `.nojekyll`, `.gitignore`를 확인합니다.
2. 기존 GitHub 저장소 **최상위 폴더(root)**의 `index.html` 및 `app.js`를 새 파일로 **둘 다 교체**하고 Commit합니다. `.nojekyll`은 유지합니다.
3. 기존 Pages 배포 설정은 그대로 사용하면 됩니다. 수정 사항이 바로 보이지 않으면 `Ctrl+Shift+R`로 새로고침하세요.
4. 새 사이트의 **데이터 업로드**에서 평일마다 받는 `.xlsx`/`.xlsm` 원본을 올립니다. **실적 파일을 GitHub 저장소에 직접 업로드할 필요는 없습니다.**

처음부터 설정한다면 Settings → Pages → Deploy from a branch → `main` / `/(root)`를 사용합니다.

## 날짜별 조회

- 업로드 시 파일 내부의 **GFA 시트에 있는 기준일**(확인이 안 되는 경우 파일명 날짜)을 기준으로 그날의 스냅샷을 저장합니다.
- 상단 **날짜별 실적 기록**에서 기준일 달력, **이전 기록 / 다음 기록**, 저장된 날짜 버튼을 누르면 해당 날짜의 팀·인원·매체·계정 실적이 바뀝니다.
- 다른 날짜를 선택하면 **사유·업무상태도 그 날짜의 기록으로 전환**됩니다. 동일 계정이라도 11/5 메모/상태와 11/6 메모/상태는 완전히 별개입니다.
- 날짜별 업로드 기록을 기존 **5개 제한 없이** 저장합니다. 단, 브라우저 저장 용량이 한정되므로 주기적인 백업이 중요합니다.
- 같은 기준일에 여러 번 업로드하면 날짜 화면에서는 **그날 가장 나중에 올린 파일**을 표시합니다. 그 날짜의 기존 메모/상태는 그대로 유지됩니다.
- **업로드하지 않은 날짜는 데이터가 없습니다.** ‘오늘 날짜’를 눌렀을 때 오늘 업로드가 없으면 알림을 표시하고 마지막 조회일 화면은 그대로 둡니다. 어제 데이터를 오늘 실적으로 대체하지 않습니다.
- 계정별 ‘이전 업로드 대비’는 **직전 저장 날짜와 비교**합니다(동일 날짜의 다른 업로드와 비교하지 않음).
- 해당 날짜가 속한 달에 맞게 **전월 매출 / 당월 목표 / 당월 예상** 표 헤더가 바뀝니다.

## 기존 기록 보존 및 백업

- 과거 버전에서 저장한 **업로드 스냅샷은 IndexedDB 내에서 그대로 유지**됩니다. 첫 진입 시 업그레이드가 진행됩니다.
- 이전 버전은 날짜 구분 없이 사유·업무상태를 저장했으므로, **기존 입력 메모/상태는 이전 버전에서 마지막으로 조회한 날짜에 최초 1회 이관**합니다. 이전 버전에 저장되지 않았던 과거 날짜별 메모를 추정 생성하지는 않습니다.
- **전체 백업 JSON**은 모든 저장된 날짜의 업로드 기록과 날짜별 메모·업무상태를 포함합니다. 새 버전은 `team23-v2` 형식을 사용하며 **기존 `team23-v1` 백업 복원도 지원**합니다.
- **사유 포함 CSV** 또는 **계정 상세 CSV**는 현재 화면에서 **선택한 기준일**의 기록만 내보냅니다. CSV 첫 열에 날짜가 표시됩니다.

## 저장 및 보안 유의사항

- GitHub Pages는 **정적 웹사이트**입니다. 엑셀 데이터와 담당자별 메모는 업로드한 **현재 PC·브라우저 프로필**의 저장소에만 들어갑니다. GitHub, 다른 PC, 팀원의 브라우저에 자동 동기화되지 않습니다.
- 브라우저 데이터를 삭제하거나 시크릿 창을 사용하면 기록이 사라질 수 있습니다. **전체 백업 JSON을 정기적으로 내려받아 별도 안전한 위치에 보관**하세요.
- 엑셀, 매출 CSV, 백업 JSON은 GitHub 공개 저장소에 업로드하지 마세요. `.gitignore`에서 일반적인 확장자/패턴을 막지만, 웹의 수동 업로드에는 별도의 확인이 필요합니다.
- 여러 팀원이 실적과 업무상태를 함께 관리하려면 별도 인증·데이터베이스를 붙여야 합니다. 현재 버전은 계정공유/로그인 기능이 없습니다.
- ‘매출’은 업로드된 **추가수수료 프로모션 매출 지표**이며 광고주의 구매 전환매출·ROAS가 아닙니다.

## 구성 파일

- `index.html` — 기존 대시보드, 날짜 선택 UI, 표 레이아웃과 상태 색상
- `app.js` — 엑셀 파싱, 2-3팀 필터, 날짜별 스냅샷/사유/업무상태 저장, 백업·복원
- `.nojekyll` — Pages 배포
- `.gitignore` — 일반적인 매출 파일 업로드 사고 방지
