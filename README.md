# 김재현 2-3팀 매출 운영 대시보드

네이버 추가수수료프로모션 엑셀 원본 파일을 **웹 화면에서 직접 업로드**하여 쇼핑검색광고 · 파워링크 · GFA 실적과 인원·계정별 부족액을 분석하는 정적 웹 대시보드입니다.

## GitHub Pages 배포

1. GitHub에 대시보드용 저장소를 생성합니다.
2. 이 ZIP을 압축 해제한 뒤 `index.html`, `app.js`, `.nojekyll`을 **저장소 최상위(root)** 경로에 업로드/커밋합니다. `README.md`도 함께 올려도 됩니다.
3. 저장소 **Settings → Pages → Build and deployment → Source: Deploy from a branch**를 선택합니다.
4. Branch를 `main`, Folder를 `/(root)`로 지정하고 **Save**를 선택합니다.
5. 배포된 Pages 주소에서 대시보드를 실행하고 **데이터 업로드**에서 `.xlsx` 또는 `.xlsm`을 선택합니다.

별도의 API·서버·외부 CDN·빌드 도구가 필요하지 않습니다. 최신 Chrome 또는 Edge를 권장합니다.

## 사용 방법

- `데이터 업로드`에서 원본 `네이버 11월 추가수수료프로모션_1105.xlsx` 같은 형식의 엑셀을 올립니다. 새로운 날짜 파일도 같은 구조라면 그대로 사용할 수 있습니다.
- **소속 `2-3팀(김재현)`인 상세계정만** 집계하고, **최연아·안희성은 소속 표기와 무관하게 제외**합니다.
- 인원별·매체별·계정별 성과와 부족액을 확인합니다. **사유/조치 메모**와 **업무상태**는 각 매체/계정ID 기준으로 저장됩니다. 엑셀을 다시 올려도 같은 매체/계정ID라면 유지됩니다.
- 최근 5회의 파일 업로드 기록이 저장됩니다. 이전에 올린 자료와 계정별 예상 매출 증감을 비교할 수 있습니다.
- **전체 백업 JSON**에는 업로드 기록, 사유, 업무상태가 담깁니다. 수시로 내려받아 안전한 곳에 보관하고, 필요시 **백업 복원**에서 다시 불러오세요.
- 상단 **사유 포함 CSV**는 전체 계정을 내보내며, 계정 상세의 **CSV 내보내기**는 현재 적용한 필터를 기준으로 내보냅니다.

## 개인정보·보안 및 저장의 중요 제한

- **GitHub 저장소 파일에는 광고계정·매출 데이터가 들어 있지 않습니다.** 배포 직후에는 비어 있는 대시보드가 표시됩니다.
- 업로드한 엑셀은 브라우저 내부에서만 읽고, GitHub 또는 다른 서버로 전송하지 않습니다. 인터넷이 끊겨도 파일 로직은 동작할 수 있습니다.
- **업로드 기록과 메모는 업로드한 브라우저/프로필의 IndexedDB 또는 localStorage에만 저장됩니다.** 다른 컴퓨터·브라우저·팀원에게 자동 동기화되지 않습니다. 시크릿 창이나 브라우저 데이터 삭제 시 소실될 수 있습니다.
- 저장 기능이 차단된 브라우저에서는 임시 표시만 될 수 있으니 백업을 반드시 내려받으세요.
- GitHub Pages 웹사이트는 공개될 수 있습니다. 따라서 원본 엑셀, CSV, 백업 JSON을 Pages 저장소에 커밋하지 마세요. 여러 명이 같은 사유·업로드 내용을 동시에 보려면 인증과 별도 데이터베이스(예: Supabase)를 추가해야 합니다.
- 수치는 원본의 **추가수수료 프로모션 매출**이며 광고주의 구매 전환매출 및 ROAS가 아닙니다. 매출 목표는 매체별 상세 파일 기준, 예상 차액 = 예상 매출 - 목표로 계산합니다. 원본 내 `raw` 일별 데이터와 매체별 누적금액이 불일치하는 계정은 최근 평일 추이를 생략합니다.

## 포함 파일

- `index.html` — 화면과 스타일
- `app.js` — XLSX 읽기, 집계, 날짜별 히스토리, 관리 메모, 백업 기능
- `.nojekyll` — GitHub Pages 정적 배포 설정
- `.gitignore` — 엑셀 및 백업 JSON의 실수 업로드 방지
